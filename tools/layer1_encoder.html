Input and segmentation

Inspect how text or raw bytes become QR data segments: mode indicators, character-count indicators and payload bits. No terminator, byte padding, Reed–Solomon correction or matrix rendering is performed here.

1. Input data

Automatic segmentation can mix numeric, alphanumeric, byte and QR Kanji modes.

Enter two hex digits per byte (spaces, commas, colons, underscores, hyphens or 0x prefixes accepted). Raw bytes are always encoded in QR byte mode; no character encoding is assumed.

2. QR parameters

Default: version 2, as in the QRgen project.

Used only to check data-bit capacity.

An ECI marker is 12 bits (0111 + 00011010). It identifies the byte encoding but is not a data segment with a character count.

Layer 1 includes the version-dependent character-count width and can validate against the selected ECC capacity. Layer 2 supplies the terminator and padding bytes.

Character count is in digits/characters for numeric, alphanumeric and Kanji, but in encoded bytes for byte mode. ECI has no character-count field. All values are bit-exact and exclude Layer 2 processing.
